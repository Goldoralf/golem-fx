# gfx-bench

> **Status: PROPOSED** — design, no code yet.

The offline render and measurement tool of golem-fx. It answers two questions for every effect, without
a host and in seconds:

1. **Is it correct?** Latency, determinism, clicks, noise, aliasing, denormals, CPU — measured, with
   pass / fail thresholds.
2. **How does it sound?** Renders of reference DIs, parameter sweeps, blind level-matched A/B.

It does **not** prove that the VST3 behaves in a real host: that is golem's side
(`tools/check-engine-blocks.py`, `tools/check-engine-parity.py`, run by the rack session — see the
[golem contract](../docs/golem-contract.md)). gfx-bench tests the DSP; golem tests the plugin in its
engines.

## 1. How an effect is reached

Each effect crate (`gfx-gate`, `gfx-chorus`…) has two layers:

- a **processor**: a plain Rust struct built on gfx-dsp, with its parameters as a plain struct keyed by
  the same ids as the plugin (`thresh`, `attack`…). No nih-plug.
- a **wrapper**: the nih-plug plugin, behind a cargo feature `plugin`. It only maps nih-plug parameters
  onto the processor's and calls it.

gfx-bench links the processors directly (feature `plugin` off). What it measures is exactly what runs in
the plugin, minus the wrapper; the wrapper is kept thin enough that golem's host checks cover it.

## 2. Commands

| Command | Does |
|---|---|
| `gfx-bench render <effect> --in <wav> [--set id=value…] [--preset <file>] --out <wav>` | One render. Sample rate and channel count follow the input; `--stereo` duplicates a mono input |
| `gfx-bench sweep <effect> --in <wav> --param <id> --values a,b,c` | One render per value, named after it, for listening to a parameter's travel |
| `gfx-bench check <effect>` | Runs the effect's whole measurement suite (§4, §5); writes `report.json` and `report.md`; exit code ≠ 0 on any failure |
| `gfx-bench blind <a.wav> <b.wav>` | Level-matches the two files, writes them as `X.wav` / `Y.wav` in a random order, hides the answer in `key.json` |
| `gfx-bench reveal <dir>` | Shows which was which, and records the listener's choice |
| `gfx-bench signals` | Writes the synthetic test signals (§3) as WAV, for use elsewhere (REAPER, golem's tools) |

Outputs go to `bench-out/` (git-ignored). Renders are 32-bit float WAV.

## 3. Signals

- **golem DIs**: `~/golem/library/di-refs/` (48 kHz, 24-bit, mono), path overridable by `GFX_DI_DIR`.
  They are read, never copied into this repo. Today: 7 guitar takes (clean, lead-clean, funk, crunch,
  high-gain, djent, lead); bass and voice are still to record; keys exist as MIDI only.
- **Synthetic**, generated deterministically by gfx-bench:
  - impulse; silence; DC and sine steps (open / close timing);
  - slow level ramps up and down (thresholds, hysteresis);
  - sine at fixed frequencies and log sweeps 20 Hz – 20 kHz (response, harmonics, aliasing);
  - a burst followed by long silence (denormals, tails, noise floor);
  - pink noise with a fixed seed (modulated effects: long-term third-octaves, level);
  - a decaying low E (82 Hz) from 0 dBFS to silence (gate chatter on low notes).
- **golem's pink noise** is generated by numpy in `check-engine-parity.py`; to compare with golem's
  renders, gfx-bench reads it as a WAV exported once, rather than re-implementing numpy's generator.

## 4. Measurements common to every effect

| Check | How | Pass |
|---|---|---|
| Latency | impulse in, first sample out (dry path and wet path) | 0 samples, unless the effect reports latency |
| Determinism | render twice from a fresh processor | bit-identical |
| Block-size independence | render with blocks of 1, 32, 64, 512, 4096 samples | identical (or ≤ −120 dB difference where smoothing is block-based) |
| Sample rates | every check at 44.1, 48, 96, 192 kHz | same results within tolerance |
| Silence and denormals | burst then 10 s of silence: output decays to exact 0 or a bounded floor; per-sample time does not climb | no NaN / inf; floor ≤ −140 dBFS unless the effect adds noise on purpose; no slowdown |
| Parameter steps | each continuous parameter jumped min → max mid-signal | no click: HF energy burst ≤ a per-effect bound |
| Structural changes | each enum / bool toggled mid-signal | no click (crossfade works) |
| Extreme values | every parameter at its min and max, input at +12 dBFS | no NaN / inf, output bounded |
| CPU | ns per sample, mono and stereo, release build | below a per-effect budget; reported every run |
| Mono / stereo | mono layout vs stereo layout with the same input on both channels | stereo L = R = mono output, unless the effect is stereo by nature |

## 5. Effect suites

Each effect adds its own measurements (open time of a gate, gain curve of a compressor, interpolation
error of a chorus…). They are specified in the effect's design document and live in its crate, run by
`gfx-bench check <effect>`.

## 6. Listening

- **Renders on reference DIs**, at the effect's default and at golem's block presets
  (`~/golem/library/block-presets/<type>/`) when the effect stands for a golem block.
- **Blind A/B, level-matched**: our effect against the block it replaces (REAPER renders produced on
  golem's side), or two versions of ours. Level matching is by integrated loudness (ITU-R BS.1770, K-weighted) —
  RMS over-weights lows; for dynamics effects, loudness over the sustained part.
- Some effects can only be judged in context: a gate before a high-gain amp, a chorus after a cab. For
  those, the rack renders the full chain through golem; gfx-bench supplies the effect's renders and
  checks only.
- **Reference recordings** of the real units (e.g. the open-source Juno-60 chorus recordings) live outside
  the repo (`GFX_REF_DIR`); `gfx-bench blind` matches levels before comparing ours against them.
- **Playing it**: every effect also builds as a nih-plug **standalone** (JACK / PipeWire), so a voicing can
  be judged guitar in hand before it ever reaches golem.
- **Applications**: each effect's design ends with an Applications table; the bench renders one file per
  row (`gfx-bench apps <effect>`), so every promised use is heard at least once.

## 7. In CI

`cargo test` runs the measurements of §4 and §5 on short synthetic signals (no DI needed), so a push
that breaks latency, determinism or click-freedom fails without anyone listening.
